# Git と PR の進め方

現場の開発と同じ流れで進めます。慣れるまでは、このページを見ながらで大丈夫です。

## 流れ

1. **Issue を立てる**（やることを1つ決める）
2. **ブランチを切る**
3. **コードを書いて、コミットする**
4. **ブランチを push して、PR（プルリクエスト）を出す**
5. **レビューを受ける**（コメントが付きます）
6. **修正して、もう一度 push する**
7. **マージする**
8. `main` に戻って、最新を取り込む

## コマンド

```
# 最新の main を取り込んでから、ブランチを切る
git switch main
git pull
git switch -c feature/item-list

# 変更をコミットする
git add .
git commit -m "一覧画面を追加"

# GitHub に上げる（初回）
git push -u origin feature/item-list
```

push のあと、GitHub のページに出る「Compare & pull request」から、PR を作ります。

## ブランチ名

`種類/内容` の形にします。

- `feature/item-list`（機能を足す）
- `fix/form-validation`（直す）
- `docs/readme`（文章だけ）

## コミットメッセージ

「何をしたか」を、短く書きます。

- 良い例：`一覧画面を追加`、`追加フォームの入力チェックを修正`
- 避けたい例：`修正`、`更新`、`aaa`

## PR は小さく出す

- **1つの PR には、1つの目的だけ**を入れます。
- 目安は、1〜2日で書ける量です。大きくなりそうなら、分けます。
- 小さい PR の方が、レビューが早く返り、直しも少なくて済みます。これは現場でも同じです。

## レビューを受けるとき

- コメントには、**必ず返信**します（直した、または、こう考えたのでこのままにした）。
- 指摘は、あなたを責めるものではありません。「なぜこうしたの？」という質問も多いです。**理由を自分の言葉で答える練習**だと思ってください。
- 直したら、同じブランチに push するだけで、PR に反映されます。

## 困ったとき

- 間違えても、たいていは元に戻せます。慌てて消さずに、**そのままの状態でチャットで相談**してください。
- `git status` の出力を貼ってもらえると、状況が分かります。
