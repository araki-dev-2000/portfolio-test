# GitHub Projects のボードの作り方

やることを見える形にして、「今、何をしているか」を一緒に確認するためのボードです。

## まず、全体のイメージ

- **Issue（やること）** は、リポジトリの中に作ります。
- **Project（ボード）** は、リポジトリの**外**、自分のアカウントの Projects に作ります。
- ボードに、リポジトリの Issue を**追加**して、列（状態）を動かしながら進めます。

順番は、次のとおりです。

1. リポジトリを作る（このテンプレートから）
2. Project（ボード）を作る
3. リポジトリで Issue を作る
4. Issue をボードに追加する
5. 作業が進んだら、列を動かす

## 作り方

1. GitHub の右上の自分のアイコン → 「Your profile」→「Projects」を開きます。
2. 「新しいプロジェクト」を押します。
3. レイアウトは「ボード」を選び、名前を付けて（アプリの名前でOKです）、「プロジェクトの作成」を押します。
4. リポジトリの「Issues」→「New issue」から、Issue を作ります（`.github/ISSUE_TEMPLATE` の「タスク」が使えます）。
5. ボードの一番下の「項目の追加」の欄に、**Issue の URL を貼って** Enter を押すと、追加されます。

画面の名前は、GitHub の更新で変わることがあります。見つからないときは、スクリーンショットを送ってください。

## 列（状態）は4つだけ

| 列 | 意味 |
|---|---|
| Todo | やることが決まっている（Issue は立てた） |
| In progress | 今、取り組んでいる |
| In review | PR を出して、レビュー待ち |
| Done | マージ済み |

初期設定では「In review」がありません。状態（Status）の項目に、あとから追加してください。

## 運用のルール

- **1つの Issue は、1つの PR** にするのが目安です。
- **In progress は、同時に2つまで**にします。増えると、どれも終わらなくなります。
- 面談の最初に、ボードを一緒に見ます。「先週どこまで進んだか」「今週何をやるか」を、ここで決めます。
- 迷ったら、Issue を小さく分けます。

## メンターにボードを見せる

ボードは、初期設定では、自分しか見られません。面談で、画面共有で見せるか、ボードの設定で共有するかを決めます。

## Issue の例（第1週）

- 設計メモを書く（`docs/design-memo.md`）
- テンプレートを動かして、最初のページ（`app/page.tsx`）を自分のアプリ用に書き換える
- 最後に書く README の雛形（`docs/readme-template.md`）に、目を通しておく
